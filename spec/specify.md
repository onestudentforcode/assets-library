# 功能规格：多模态素材库 MVP

**功能分支**：`001-multimodal-asset-library`
**状态**：实施中
**技术约束**：Next.js、TypeScript、Tailwind CSS、shadcn/ui、pnpm

## 用户故事

### P1：上传并分析本地素材

内容运营人员可以一次选择一个或多个图片/视频，在固定高度的滚动列表中逐项悬停预览，并看到各自的真实上传进度、处理状态以及明确失败原因。图片以独立素材请求上传；上传页中的视频以分镜批次请求上传，系统在后台切分自然分镜，并将每个分镜作为独立视频素材进行分析。

验收条件：

1. JPEG、PNG、WebP 图片不超过 20 MB 时可提交；结果包含描述、分类标签和 OCR 或不可用原因。
2. H.264 编码的 MP4 不超过 200 MiB 时可提交为分镜批次；批次切分后的每个分镜不得超过 7 MiB，每个合格分镜生成一个独立视频素材，结果包含视觉描述、主题、标签、视觉分段、关键时间点和时间轴。
3. 音频、URL、其他容器、非 H.264 MP4、损坏文件和超限文件被拒绝，并显示具体原因。
4. 分镜批次必须在任何子素材解析开始前取得并校验完整分镜清单，并在下载时再次核对实际字节数；任一分镜超过 7 MiB 时，批次以 `file_too_large` 失败，不创建任何子素材。
5. 合格分镜进入原有视频解析链路：不足或等于 5 秒时提取 `ceil(时长秒数)` 帧，超过 5 秒时固定提取 5 帧；各帧位于等分区间中点，长视频对应 10%、30%、50%、70%、90%。
6. Responses 协议或禁用视频能力时，视频任务失败为 `model_video_unsupported`，不得静默改用其他分析方案；分镜批次中的任一子素材失败时，整批子素材回滚。

### P2：审核、编辑和正式入库

用户可以编辑名称、描述和标签后正式入库，也可以在上传时选择分析完成后直接入库。删除过的模型标签在重新分析后不得自动恢复。

### P3：浏览和维护素材

概览将所有上传成功且未删除的素材分为“已入库”和“待入库”两个视图，默认打开已入库，每页按 4 列 × 2 行展示 8 个素材。待入库包括排队、分析中、失败以及分析完成待确认的素材，并明确标注状态；分析完成且待审核的素材可在概览直接入库。详情展示原始信息、原文件预览、处理状态、分析结果和最终元数据，并允许按原始文件名下载上传文件。

### P4：按来源批次管理视频分镜

内容运营人员上传一个原视频后，可以持续查看分镜批次状态和已创建子素材的处理状态。通过大小校验的分镜在解析期间出现在素材概览，并标注来源原文件名；批次结束前不得单独发布、重试或删除其中的子素材。

验收条件：

1. 批次状态依次使用 `queued`、`splitting`、`validating_segments`、`analyzing`、`completed` 或 `failed`，进度不得倒退，终态进度为 100%。
2. 所有分镜通过大小校验后一次性创建子素材，名称使用“原文件基础名-分镜-三位序号”，素材仅展示来源原文件名，不长期保存或展示分镜序号和时间范围。
3. 任一子素材解析失败时，批次继承该失败码和可操作说明，整批子素材从概览移除并清理文件；用户只能重新上传原视频。
4. 未选择直接入库时，所有分镜均成功后统一进入待审核；选择直接入库时，所有分镜均成功后统一正式入库，不得出现部分入库。
5. 分镜下载完成后删除原视频文件；任一环节终态失败时也删除原视频。来源批次记录和原文件名长期保留，外部分镜任务无论成功或失败都应被清理。
6. 批次成功后，各分镜素材恢复为可独立编辑、发布、重试和删除的普通视频素材。

## 功能需求

- 上传页允许一次选择多个本地文件，并按选择顺序发送独立 multipart 请求；图片使用单素材接口，视频默认使用分镜批次接口，旧视频单素材接口继续保留兼容。
- 上传框保持固定高度；素材列表一行一个文件，默认显示文件名，悬停或聚焦时展开本地预览，超出区域可滚动。
- 图片支持 JPEG、PNG、WebP；视频只支持 MP4/H.264。
- 上传限制默认为图片 20 MiB、原视频 200 MiB，并允许环境变量覆盖；分镜大小上限固定为 7 MiB（`7 × 1024 × 1024` 字节），等于上限时允许处理。
- 单素材处理状态为 `queued`、`validating`、`analyzing`、`completed`、`failed`；分镜批次处理状态为 `queued`、`splitting`、`validating_segments`、`analyzing`、`completed`、`failed`。
- 审核状态为 `pending_review`、`published`、`deleted`。
- 支持 OpenAI Chat Completions 和 Responses 两种兼容协议。
- 模型配置和密钥只通过环境变量注入。
- Chat Completions 视频分析使用带时间点标注的多图片输入；Responses 默认不支持视频。
- Qwen3.7 结构化素材提取默认关闭思考模式，并允许通过环境变量显式覆盖。
- 视频由 worker 在 `validating` 阶段使用 FFmpeg 抽取 JPEG 关键帧；关键帧随素材持久化，重试时直接复用。
- 分镜批次在后台调用专用场景检测服务，完整清单通过大小校验后再下载并创建子素材；空清单、非法响应、服务不可用、超时或分片下载失败统一标记为 `scene_split_failed`。
- 分镜子素材与来源批次保持内部一对多关联，对外仅增加可空的来源原文件名；普通素材的来源原文件名为空。
- 分镜批次成功前，子素材不得执行发布、重试或删除；任何子素材解析失败都会触发整批软删除和媒体清理。
- 支持上传状态、素材分页、详情、编辑、发布、重试、软删除和 Range 媒体读取 API。
- 上传页离开后停止页面轮询，但已入队任务继续由 worker 处理；worker 使用任务心跳并周期恢复失联任务。
- 素材上传成功后立即出现在概览；概览在存在非终态素材时自动刷新，并支持对已完成待审核素材直接入库。
- 素材概览仅在“已入库”视图支持按标签值进行大小写不敏感的包含搜索；待入库素材、名称和描述不得参与匹配。
- 失败必须包含稳定错误码和可操作的中文说明。

## 成功标准

1. 对任意分镜批次，100% 的分镜均在首个子素材解析请求前完成大小校验。
2. 任一分镜超过 7 MiB 或任一子素材解析失败时，最终可见的批次子素材数量为 0。
3. 所有分镜成功时，用户看到的子素材数量与分镜服务返回的数量完全一致，且每个素材都能识别来源原文件名。
4. 直接入库批次只能出现“全部已入库”或“全部未入库”两种结果，不出现部分入库。
5. 后台处理进程中断并恢复后，同一来源批次不得产生重复子素材。
6. 旧视频单素材接口和图片上传的既有验收场景保持全部通过。

## 非功能需求

- 素材库主应用代码继续使用 TypeScript strict；视频场景检测和分镜功能继续使用现有 Python Scene Detection Service 实现，通过独立进程和 HTTP 接口接入，不移植或重写为 TypeScript。
- 200 MiB 上传不得通过 `request.formData()` 整体载入内存。
- 分镜批次调用场景检测服务的单次等待上限默认为 600 秒，超时必须形成可查询的失败状态。
- SQLite 使用 WAL、忙等待和事务任务抢占。
- 媒体路径必须限制在配置的存储根目录下。
- 素材概览在 1,000 条数据下应在 3 秒内返回首屏分页。

## 范围外

音频素材、音轨分析、ASR、语言识别、字幕输出、URL 上传、批量编辑/删除、人工分镜编辑、缩略图生成、分镜之外的主动转码、全文搜索、对象存储、Serverless、登录和权限体系。

## 依赖与假设

- 场景检测服务由素材库部署栈共同启动，但保持独立进程和 HTTP 边界。
- 本功能固定对接 `scene-detect-service` 提交 `4f29ad7141bf63c04576ecd6734578680b5968ad` 的接口契约，升级必须显式修改版本并重新验收。
- Scene Detection Service 的 Python 框架、场景检测算法和视频切分实现原则上保持原样；除容器启动、配置接入、接口契约兼容或缺陷修复确有必要外，不对其源码进行大规模改造。
- 来源批次记录长期保留用于关联和审计；原视频文件、外部分镜任务及失败批次的子素材文件不长期保留。
