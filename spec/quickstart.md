# 快速验证

## 准备

1. 安装 Node.js 22+ 和 pnpm。
2. 执行 `cp .env.example .env` 并配置模型地址、密钥和模型名。
3. 使用 Qwen3.7 时设置 `MODEL_ENABLE_THINKING=false`；Chat Completions 视频分析设置 `MODEL_VIDEO_MODE=frames` 和 `MODEL_VIDEO_TIMEOUT_MS=300000`。

## 启动

```bash
pnpm install
pnpm db:migrate
pnpm dev
```

打开 `http://localhost:3000`。`pnpm dev` 同时启动 Next.js 和 worker。

视频分镜链路需要独立 Python 服务。完整验证推荐执行 `docker compose up -d`；仅本地运行 `pnpm dev` 时，应另行启动固定提交的 Scene Detection Service，并确保其只监听 `127.0.0.1:28200`。

## 验证

1. 上传不超过 20 MB 的 JPEG/PNG/WebP，确认上传成功后立即出现在概览并显示分析状态。
2. 分析完成后在概览直接确认入库；离开上传页后确认该页不再轮询，而 worker 继续处理。
3. 打开概览确认默认进入“已入库”，其按钮位于“待入库”之前；分别切换两个视图，确认每页最多显示 8 个素材并可通过页码、上一页和下一页切换。
4. 确认标签搜索栏只在“已入库”视图出现，且搜索结果不包含任何待入库素材。
5. 通过兼容的 `/api/uploads/videos` 上传 1–5 秒 H.264 MP4，确认接口先返回排队状态，worker 在服务端分别提取 1–5 张关键帧，并生成视觉分段、关键时间点和时间轴。
6. 通过兼容接口上传超过 5 秒且不超过 200 MiB 的 H.264 MP4，确认固定取 10%、30%、50%、70%、90% 五帧，且不要求公网地址。
7. 通过兼容接口验证 Responses 视频失败为 `model_video_unsupported`；音频、多文件、错误 MIME 和超限素材在上传阶段被拒绝；HEVC、损坏媒体或抽帧失败在 `validating` 阶段标记失败。
8. 重试失败素材时确认复用已有帧；删除后确认概览、详情、媒体 URL 和素材目录均不可访问。
9. 分析期间终止并重启 worker，确认失联任务在心跳过期后重新排队并最终完成。
10. 打开素材详情，点击删除按钮旁的“下载素材”，确认响应使用原始上传文件名且文件内容可读取。

## Phase 11：视频分镜批次验收

以下步骤用于回归 Phase 11 已实现功能：

1. 通过 Compose 启动素材库和场景检测服务，确认场景检测服务只监听 `127.0.0.1:28200`，健康检查成功，素材库使用固定提交 `4f29ad7141bf63c04576ecd6734578680b5968ad`。
2. 从上传页提交一个不超过 200 MiB、可切出多个自然场景的 H.264 MP4，确认请求返回 `202`，状态经过 `queued`、`splitting`、`validating_segments` 和 `analyzing`。
3. 确认完整分镜清单通过校验后，所有分镜素材一次性出现在待入库概览，名称为“原文件基础名-分镜-三位序号”，并显示相同的来源原文件名。
4. 分别让清单元数据和实际下载内容达到恰好 `7 × 1024 × 1024` 字节，确认允许继续解析；任一处超过上限 1 字节时，确认批次以 `file_too_large` 失败，`childAssets` 为空且模型解析调用次数为 0。
5. 分别模拟场景检测服务不可用、600 秒超时、非法/空清单和分片下载失败，确认批次以 `scene_split_failed` 结束，不留下可见子素材，并尝试清理外部任务。
6. 在所有子素材分析成功前，确认发布、重试和删除操作被拒绝；批次完成后确认这些操作恢复可用。
7. 模拟任一子素材解析失败，确认批次继承失败原因，所有兄弟素材从概览移除，媒体文件进入清理流程，且只能重新上传原视频。
8. 未勾选直接入库时，确认全部分镜成功后统一进入待审核；勾选时确认全部分镜在同一结果中正式入库，不出现部分发布。
9. 在切分、下载和子素材创建阶段分别终止 worker，恢复后确认任务可继续或安全失败，同一批次不会产生重复素材。
10. 调用旧 `/api/uploads/videos` 和图片上传接口，确认仍保持单素材响应与既有处理行为；上传页视频默认请求 `/api/uploads/video-scenes`。
11. 确认分镜下载完成或批次终态失败后原视频已删除，批次记录和来源原文件名仍可查询；成功或失败后外部分镜任务均被尽力删除。
